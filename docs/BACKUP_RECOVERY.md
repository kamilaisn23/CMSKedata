# Backup dan pemulihan — tahap 5

Versi 1.0, 2026-11-09. Pengguna mengizinkan tahap berikutnya secara hemat. ADMIN saja dapat membuat, mengunduh, memeriksa, dan memulihkan paket. Pemulihan menghasilkan folder data baru; tidak menimpa database/media aktif. Aktivasi folder hasil pemulihan dilakukan operator lewat konfigurasi dan restart setelah memeriksa hasilnya. Tidak menjalankan restore atas data pengguna saat implementasi atau tes.

Paket `.kdbackup.gz` adalah JSON gzip berversi, berisi snapshot SQLite konsisten dan seluruh file reguler pada folder uploads (flat), dengan ukuran/checksum SHA-256 setiap file. Tidak mencakup source, `.env`, atau salinan editor browser. Sesi login dihapus dari snapshot, bukan database aktif. Batas versi sederhana: 64 MiB data mentah, 96 MiB paket/JSON terurai, 10.000 file. Folder media bertingkat/symlink ditolak agar backup tidak parsial. Paket mengandung data workspace sensitif; folder penyimpanan privat `.backups/` diabaikan Git dan tidak disajikan static server.

Saat backup, penyimpanan admin baru ditahan (503), lalu tunggu request mutasi lama selesai sebelum snapshot/copy. Batas tunggu 15 detik; kunci dilepas pada sukses/gagal. Pembacaan tetap tersedia. Backup otomatis/jadwal/cloud bukan cakupan batch ini.

Validasi sebelum restore: magic/format/versi, batas ukuran sebelum/sesudah dekompresi, base64 dan checksum, nama file aman/unik (termasuk Windows), integritas/FK SQLite, tabel/kolom sesuai Prisma saat ini, tanpa views/triggers/virtual tables, serta file Media lokal yang dirujuk tersedia. Tidak menerima SQL untuk dieksekusi atau path tujuan dari HTTP. Restore masuk `.backups/restored/<uuid>/database.sqlite` dan `/uploads`, baru dipublikasikan dari staging setelah lengkap. Salinan Session selalu dibersihkan lagi.

Kontrak admin: GET `/backups` daftar metadata; POST `/backups` membuat backup; GET `/backups/:id/download`; POST `/backups/inspect` multipart file (96 MiB maksimum) memvalidasi dan memberi ringkasan; POST `/backups/:id/restore` body `{confirmation:"PULIHKAN"}` menghasilkan folder baru. 400 paket/body invalid, 401 tanpa sesi, 403 bukan ADMIN, 404 ID hilang, 409 operasi sibuk, 413 terlalu besar, 500 kegagalan internal tanpa membocorkan isi data. Audit mencatat CREATE_BACKUP/PREPARE_RESTORE, tanpa isi paket.

Konfigurasi opsional: `BACKUPS_DIR` default `<project>/.backups`, harus di luar public; `UPLOADS_DIR` default `<project>/public/uploads`. SQLite DATABASE_URL tetap diselesaikan relatif terhadap prisma/schema.prisma. Node 24+ diperlukan, sama seperti script migrasi lokal. Tidak ada migrasi/dependensi baru.

Aktivasi manual: hentikan instance yang memakai data lama; simpan konfigurasi lama untuk rollback; set DATABASE_URL ke `file:<path absolut hasil restore>/database.sqlite`, UPLOADS_DIR ke `<path absolut hasil restore>/uploads`; hidupkan server dan periksa health, login, daftar situs/konten/media. Server `/uploads` hanya membaca folder yang dikonfigurasi (tanpa fallback ke media lama). Jika pemeriksaan gagal, hentikan dan kembalikan kedua konfigurasi ke nilai lama. Folder lama tetap utuh. Backup tersimpan pada server yang sama bukan pengganti salinan di perangkat/lokasi lain: unduh paket ke lokasi pribadi terpisah.

Uji hanya fixture DB/media sementara: round trip backup/restore, snapshot konsisten tanpa sesi, corrupt/traversal/duplikat/ukuran/schema/FK/media hilang ditolak, hanya ADMIN, pause/drain/failure cleanup, tidak menimpa tujuan/data aktif; UI daftar/create/download/inspect/konfirmasi restore dengan API fixture. Lint, build dan suite proyek harus lulus.
